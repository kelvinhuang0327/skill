# TSD Template Rules

## Purpose

This document defines the mandatory rules for Word template usage in TSD generation.
All TSD must be generated by cloning the designated template source.

Created: 2026-05-11

---

## Template Source

**Runtime canonical path:**

```
assets/base_template.docx
```

**Ownership:** the base-template `.docx` is an **operator-supplied local build input**.
It is NOT part of the Git-owned canonical source. The runtime materializer receives it
through an explicit input argument and materializes it byte-for-byte to the canonical
runtime path above.

**Identity:** the base template is identified by its content SHA-256, not by its local
filename or path.

**Role:** Primary Word template source for all TSD generation.

---

## Rules

### T1 — Template Clone Mandatory (CRITICAL)

TSD generator MUST open the template and clone it as the base document.

```python
# CORRECT
doc = Document("<runtime>/assets/base_template.docx")

# WRONG — loses all styles, TOC, header/footer, bookmarks, section 4-11
doc = Document()
```

**FAIL if** `Document()` (blank) is used as the TSD base.

---

### T2 — Do Not Generate from Blank docx

Never create the full TSD structure from scratch using python-docx API calls.

The following are FORBIDDEN as full TSD construction approaches:
- `Document()` followed by manual heading/paragraph insertion
- Building TOC programmatically without template TOC structure
- Inserting Header/Footer XML manually
- Rebuilding section 4–11 content from scratch

---

### T3 — Header / Footer Preservation (CRITICAL)

Header and Footer XML from the template MUST be preserved intact.

**Do NOT:**
- Replace `<w:hdr>` or `<w:ftr>` XML
- Remove page number fields from Header/Footer
- Delete or recreate the Header/Footer section

---

### T4 — TOC Preservation (CRITICAL)

The TOC structure must be preserved and only updated via the designated API.

**Correct approach:**
- Find `<w:hyperlink>` within each TOC paragraph
- Update only the section number run and title run inside `<w:hyperlink>`
- Preserve `<w:tab/>` and webHidden PAGEREF field runs untouched
- `rStyle` must remain `'ae'`; `rFonts eastAsia='標楷體'`

**Do NOT:**
- Use `set_text()` on entire TOC paragraphs
- Delete and re-insert TOC paragraphs
- Rebuild the TOC structure from scratch

---

### T5 — Section 4–11 Preservation (CRITICAL)

Sections 4 through 11 (and any section beyond section 3) MUST be preserved exactly as they appear in the template:

- Section 4: System Interfaces
- Section 5: Performance and Capacity
- Section 6: High Level Deployment Framework
- Section 7: Security & Control
- Section 8: Program Specifications
- Section 9: Change History
- Section 10: Document Reviews
- Section 11: Document Approvals

**Do NOT** delete, clear, or overwrite these sections.

---

### T6 — Cover Page Preservation

The cover page (including document title, project fields, logo) MUST be preserved from the template.

When required, update only:
- Project name field
- Document date field
- Document version field

**Do NOT** rebuild the cover page layout.

---

### T7 — Appendix Style Preservation

The appendix style definitions (`v24heading1`, `v24heading2`, `v24ListBullet`) MUST come from the template.

**`proto_bullet` source rule:**
```
proto_bullet = doc.paragraphs[appendix_title_idx + 2]
```
(index +2, NOT +1 — +1 is `v24heading2`, +2 is `v24ListBullet`)

---

### T8 — Replacement Scope (CRITICAL)

Only the following may be replaced or added when generating a new TSD:

| Section | Allowed Operation |
|---|---|
| 3.x heading text | Title update only |
| 3.x.1 body paragraphs | Full replacement |
| 3.x.2 programme list | Full replacement; content per `core/CHANGE_PROGRAM_CONTRACT.md` (placement-dependent) |
| 3.x.3 diff tables | Diff cell content replacement |
| Appendix section headings | Title text update only |
| Appendix file bullet list | Full replacement |
| Project name / date / version | Field update (cover page) |

**Everything else MUST remain from the template.**

---

## Forbidden Operations

The following are absolutely forbidden during TSD generation:

| Operation | Reason |
|---|---|
| `doc = Document()` as full TSD base | Loses all styles and structure |
| Manual reconstruction of full document | Error-prone; loses field codes |
| Replacing Header/Footer XML | Breaks page numbering |
| Replacing TOC structure | Breaks hyperlinks and PAGEREF |
| Deleting section 4–11 | Required content in deliverable |
| Rebuilding appendix style from scratch | Loses `v24ListBullet` definition |
| Importing appendix style from different docx | Style conflicts |

## Template Provides (Complete List)

- Cover page with field codes
- Document metadata table
- Table of Contents with hyperlink structure and PAGEREF fields
- Header with project name and section title
- Footer with page number and document version
- Section 1: Preamble
- Section 2: System Overview
- Section 4: System Interfaces
- Section 5: Performance and Capacity
- Section 6: High Level Deployment Framework
- Section 7: Security & Control
- Section 8: Program Specifications
- Section 9: Change History
- Section 10: Document Reviews
- Section 11: Document Approvals
- Appendix style definitions
- Heading styles: `v24heading1`, `v24heading2`
- List bullet style: `v24ListBullet`
- Paragraph style: Normal / body text
- Table style for diff example tables
- Hyperlink / bookmark structure
- Font theme settings (Courier New for diff, 標楷體 for CJK)
- Margin and page layout settings
